# 《独家童话》3D 宠物模块设计与开发方案

## 1. 模块定位

《独家童话》的宠物模块不应只是一个简单的“换装页面”或“小游戏”，而应被设计成：

> **绘本手账风 UI + 中央真实可交互 3D 宠物 + 情侣共同养成 + 换装收藏系统**

整体目标是让宠物成为《独家童话》世界观的一部分，而不是一个独立、割裂的游戏模块。

核心体验应该围绕一句话展开：

> **让用户感觉这只宠物真的“活着”。**

---

## 2. 视觉方向

整体视觉风格延续现有《独家童话》的设计语言：

- 奶油白背景
- 暖棕色手绘线条
- 桃粉色作为强调色
- 小花、爱心、布料、木质家具等生活化元素
- 柔和圆角卡片
- 绘本、手账、纸张质感
- 禁止明显科技感
- 避免传统游戏 HUD 风格
- 避免高饱和霓虹色
- 避免黑色背景与硬核游戏 UI

中央 3D 宠物区域应像：

> **《独家童话》里一张会动、会回应用户的绘本。**

建议采用：

- 2D UI：手绘、绘本、奶油纸风格
- 3D 宠物：柔和半写实 / 风格化 3D
- 配饰列表缩略图：手绘 PNG
- 实际穿戴效果：3D GLB 配件

---

## 3. 宠物整体表现风格

不建议完全追求写实毛发效果。

推荐：

> **柔和半写实 3D**

特点：

- 头部略大
- 眼睛略大
- 四肢略短
- 外形可爱但不过度 Q 版
- 毛发通过形体与贴图表现
- 尽量减少高成本实时毛发模拟
- 保留温暖、柔软、治愈感

这样更符合：

- 《独家童话》的整体视觉
- 移动端性能要求
- 换装系统实现
- 动画制作
- 未来多个宠物扩展

# 6. 交互原则

核心原则：

> **不要让宠物互动过度依赖按钮。**

用户应该可以直接触摸宠物。

支持：

- 摸头
- 抚摸身体
- 点击耳朵
- 点击爪子
- 点击肚子
- 点击尾巴
- 左右拖动观察
- 上下有限旋转
- 双指缩放
- 宠物跟随手指看
- 根据不同部位触发不同反馈

---

# 7. 身体区域碰撞系统

给 3D 宠物模型设计多个不可见交互区域：

```text
Pet
│
├─ HeadArea
├─ EarArea
├─ BodyArea
├─ PawArea
├─ BellyArea
└─ TailArea
```

这些区域只负责：

- RayCast
- Touch Hit Test
- Interaction Detection

不参与视觉展示。

---

# 8. 点击不同部位的反馈

| 部位 | 推荐反馈 |
|---|---|
| 头部 | 闭眼、蹭手、尾巴轻摇 |
| 耳朵 | 抖耳朵、歪头 |
| 身体 | 回头看用户 |
| 爪子 | 抬爪、握手 |
| 肚子 | 翻身、躺下 |
| 尾巴 | 回头、躲尾巴、追尾巴 |

# 9. 摸头交互

摸头不能只是点击一次播放动画。

建议支持：

```text
手指按住头部
↓
左右轻轻滑动
↓
进入 PetHeadLoop
```

宠物反馈：

```text
闭眼
+
轻轻晃头
+
尾巴摇动
```

如果持续约 2 秒，可以触发：

```text
❤️ +1
```

并出现非常淡的小爱心或一句短反馈，例如：

> 好舒服呀～

---

# 10. 尾巴互动设计

尾巴建议做成具有“连续反馈”的区域，而不是始终播放同一个动画。

例如：

```text
第一次点击
↓
回头

第二次点击
↓
尾巴躲开

第三次点击
↓
转身盯着用户
```

可以出现一句：

> 不许一直碰这里！

这种多阶段反馈能显著增强宠物的生命感。

---

# 11. 左右拖动与触摸冲突规则

左右滑动存在两种含义：

1. 观察宠物
2. 与宠物互动

因此需要明确手势优先级。

推荐逻辑：

```text
Touch Start
      ↓
    RayCast
      ↓
是否碰到 Pet Collider？
      │
 ┌────┴────┐
YES        NO
 │          │
互动       Orbit Camera
```

## 空白区域拖动

控制 Camera Orbit：

- 左右：360° 查看宠物
- 上下：有限角度观察
- 双指：缩放距离

## 手指落在宠物身上

不旋转相机，进入 Interaction 模式。

例如：

- 抚摸头部
- 抚摸身体
- 摸肚子
- 点耳朵
- 点尾巴

---

# 12. Camera Orbit 观察系统

推荐让相机围绕宠物旋转，而不是直接旋转宠物模型。

控制参数：

```text
cameraYaw
cameraPitch
cameraDistance
```

推荐：

- Yaw：支持 360°
- Pitch：限制在舒适范围
- Distance：设置最小与最大缩放范围

在用户旋转到宠物背后时，可以触发额外行为：

```text
宠物轻微回头看用户
```

让“观察”本身也变成交互。

---

# 13. 宠物跟随手指看

推荐加入“宠物看着用户手指”的细节。

例如：

```text
用户手指移动
👆 →

宠物头部
🐶 →
```

Godot 中可通过：

- Skeleton3D
- Head Bone
- LookAt / Bone Modifier

实现有限角度跟随。

建议限制：

```text
Yaw   ±25°
Pitch ±15°
```

禁止头部产生夸张或不自然旋转。

---

# 14. Idle 微动作系统

宠物不能只是：

```text
Idle
→ 用户点击
→ 播放动画
→ Idle
```

真正让宠物“活起来”的关键在于微动作。

Idle 状态下随机触发：

- 呼吸
- 眨眼
- 耳朵抖动
- 歪头
- 看向旁边
- 舔鼻子
- 伸懒腰
- 尾巴轻摆
- 趴下
- 挠耳朵
- 看向主人
- 打哈欠

结构示例：

```text
Idle_Base
    │
    ├─ Blink
    ├─ EarMove
    ├─ LookAround
    ├─ TailMove
    ├─ Stretch
    └─ Yawn
```

推荐每隔约 3~8 秒根据权重随机触发微动作。

重点是避免固定循环，让用户在不操作时也愿意多看一会儿。

# 16. 动作组合系统

不要把所有行为都设计成单个动画。

例如点击「玩耍」后：

```text
LookAtUser
↓
Excited
↓
RunToBall
↓
PlayBall
↓
RunBack
↓
Happy
↓
Idle
```

建议在 Godot 内抽象：

```text
ActionSequence
```

示例：

```gdscript
play_sequence([
    "look_user",
    "excited",
    "run_ball",
    "play_ball",
    "return",
    "happy"
])
```

这样后续可以持续组合复杂行为，而不需要为每一种行为制作一个完整大动画。

# 18. 换装实现方式

第一阶段不建议使用复杂布料系统。

建议所有配饰采用 Socket / Attachment 挂点系统。

例如：

```text
Skeleton3D
│
├─ HeadSocket
├─ NeckSocket
├─ BackSocket
└─ TailSocket
```

对应：

```text
帽子
→ HeadSocket

围巾 / 领结
→ NeckSocket

小背包
→ BackSocket

尾巴蝴蝶结
→ TailSocket
```

这样更容易：

- 更换配件
- 扩展新配饰
- 保证移动端性能
- 让 Codex 帮助开发
- 兼容多个宠物

# 20. 情侣共同养成

情侣能力应该成为该宠物系统区别于普通虚拟宠物游戏的核心特征。

例如：

```text
小满：
摸了一下糯米

↓ 服务端同步

阿舟打开 App：

糯米跑过来
+
气泡：
「刚刚小满摸过我哦」
```

还可以记录：

- 今天谁喂食了
- 谁陪玩了
- 谁摸过宠物
- 两个人是否都来看过宠物
- 连续共同陪伴天数
- 最近一次互动时间

核心方向：

> 宠物成为情侣双方之间一种“非直接交流媒介”。

# 23. 数据与逻辑分层

例如宠物状态：

```json
{
  "hunger": 62,
  "happiness": 81,
  "energy": 45,
  "intimacy": 128,
  "cleanliness": 90
}
```

这些真实业务数据应由：

```text
NestJS + PostgreSQL
```

保存。

Godot 只接收状态并进行表现。

例如：

```text
energy > 70
+
happiness > 70
↓
宠物更活跃
```

```text
energy < 20
↓
打哈欠
↓
趴下
↓
睡觉
```

```text
hunger 较低
↓
看向食盆
↓
看用户
↓
表现期待喂食
```

# 24. React Native ↔ Godot 通信协议

不要让 React Native 到处直接调用 Godot 内部方法。

建议统一定义事件协议。

## RN → Godot

```text
PET_ACTION
PET_OUTFIT
PET_STATE
CAMERA_MODE
```

示例：

```ts
{
  type: "PET_ACTION",
  payload: {
    action: "feed"
  }
}
```

## Godot → RN

```text
PET_CLICK
ACTION_FINISHED
OUTFIT_CHANGED
INTERACTION
```

示例：

```json
{
  "type": "INTERACTION",
  "payload": {
    "target": "head",
    "action": "pet"
  }
}
```

目标是让：

```text
React Native
负责业务

Godot
负责表现
```

两者通过稳定事件协议解耦。

# 28. 最终目标体验示例

用户第一次进入：

```text
              糯米的小屋

          小满  ×  阿舟

        ┌───────────────┐
        │               │
        │      🐶       │
        │               │
        └───────────────┘

        它看到你来了。

              ↓

       糯米跑到镜头前

              ↓

          摇尾巴

              ↓

        「你回来啦」
```

用户摸摸头：

```text
糯米闭眼
+
蹭手
+
尾巴快速摇
```

用户左右拖动：

```text
Camera 围绕宠物旋转
```

旋转到背后：

```text
糯米轻轻回头看用户
```

点击尾巴：

```text
尾巴躲开
```

再次点击：

```text
糯米转头看用户
```

然后进入换装页，为糯米穿上：

> 小花围巾

另一半再次打开 App 时：

> 糯米已经穿着这条围巾。

最终目标不是：

> “App 里加入了一个宠物小游戏。”

而是：

> **“我们共同养了一只属于两个人的宠物，它生活在《独家童话》的世界里。”**
