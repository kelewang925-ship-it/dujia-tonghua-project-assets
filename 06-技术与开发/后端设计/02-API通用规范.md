# 《独家童话》API 通用规范

本文是全部模块接口、文件流程和异步任务共同遵循的协议。产品范围与技术边界见[后端设计入口](./README.md)和[总体架构](./01-总体架构.md)，具体端点、字段和归属见[模块 API 清单](./04-模块API清单.md)。

## 1. 基础请求约定

- 基础路径为 `/api/v1`，业务请求经 HTTPS 传输，JSON 使用 UTF-8 和 `Content-Type: application/json`。
- API JSON 字段使用 `camelCase`，数据库字段使用 `snake_case`；枚举使用稳定英文大写代码，中文说明仅用于显示。
- 核心资源 ID 为 UUID 字符串，不使用自增序号作为公开身份。客户端不得根据 ID 推导归属。
- 时间点以 UTC 写入 PostgreSQL，API 输出 ISO 8601 UTC 字符串，如 `2026-09-08T06:00:00.000Z`。输入时间点须带时区并归一到 UTC；纯日历日期使用 `YYYY-MM-DD`，不能当作 UTC 时间点换算。周期提醒涉及的时区由业务字段明确记录。
- 查询和请求体仅接受 OpenAPI 定义的字段、类型、范围及枚举。未知字段、格式错误、非法排序返回 `VALIDATION_FAILED`；客户端不能提交服务端归属或账务字段改变权限。
- PATCH 中省略字段表示不修改，显式 `null` 仅用于允许清空的可空字段。空字符串不等同于 `null`；禁止用缺失值推断清除关系。

OpenAPI / Swagger 是机器可读契约，必须注明认证、请求头、必填与可空字段、响应、错误码、幂等和版本要求。公开资料只展示业务 API，不包含内部管理入口、密钥、供应商配置或风控阈值。

## 2. 成功与错误响应

单资源成功响应示例（HTTP 200）：

```json
{
  "data": {
    "id": "94f461f7-6af6-4d4f-8a7e-52f6beac5001",
    "visibility": "PRIVATE",
    "version": 3,
    "updatedAt": "2026-09-08T06:00:00.000Z"
  },
  "meta": null,
  "requestId": "req_example_001"
}
```

错误响应示例（HTTP 409）：

```json
{
  "error": {
    "code": "RESOURCE_VERSION_CONFLICT",
    "message": "内容已更新，请刷新后再编辑",
    "details": { "currentVersion": 4 }
  },
  "requestId": "req_example_002"
}
```

成功包包含 `data`、`meta`、`requestId`；错误包包含 `error`、`requestId`，不混入成功数据。无结果的同步操作使用 HTTP 200 且 `data: null`，避免 HTTP 204 无响应体与统一包冲突。异步受理使用 HTTP 202，`data` 返回任务 ID 和当前状态，不能表示工作已完成。

服务端为每次 HTTP 尝试生成 `requestId`，同时通过 `X-Request-Id` 响应头返回。客户端来值不可直接作为可信追踪 ID。错误 `message` 为可展示中文，客户端根据稳定 `code` 映射页面状态；`details` 默认为 `null`，仅允许结构化字段校验信息或已获授权资源的冲突提示。不得返回 SQL、堆栈、完整对象键路径或供应商原始错误。

## 3. HTTP 状态码与稳定错误码

| HTTP | 语义及错误码 | 客户端行为 |
| --- | --- | --- |
| 200 | 查询、更新、删除或其他同步操作成功 | 读取统一成功包 |
| 201 | 同步创建资源成功 | 使用返回资源 ID |
| 202 | 异步任务已受理 | 通过任务查询跟踪终态 |
| 400 | `VALIDATION_FAILED`、`SMS_CODE_INVALID` | 修正字段或重新获取验证码，不自动循环重试 |
| 401 | `AUTH_REQUIRED`、`TOKEN_EXPIRED`、`INVALID_CREDENTIALS` | 缺失/无效/已撤销认证或登录失败；仅 Access Token 过期可尝试刷新 |
| 403 | `COUPLE_REQUIRED`、`COUPLE_ACCESS_DENIED`、`PRIVATE_RESOURCE`、`FILE_ACCESS_DENIED` | 按关系、私密或文件权限状态处理，不重试绕过 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在、已删除或须隐藏存在性 |
| 409 | `RESOURCE_VERSION_CONFLICT`、`IDEMPOTENCY_CONFLICT` | 刷新后合并修改，或按幂等规则处理 |
| 422 | `QUOTA_EXCEEDED`、`INSUFFICIENT_CREDITS` | 提示容量/权益不足，不能通过重复提交解决 |
| 429 | `RATE_LIMITED` | 按 `Retry-After` 秒数退避 |
| 500 | `JOB_FAILED`、`INTERNAL_ERROR` | 展示稳定提示并保留 `requestId` 供排查 |

`AUTH_REQUIRED` 包括缺失、无效或已撤销会话；`TOKEN_EXPIRED` 专用于可识别的 Access Token 到期。`INVALID_CREDENTIALS` 不区分手机号不存在或密码错误；`SMS_CODE_INVALID` 不区分验证码错误、失效或已使用。短信发送响应不能泄露账号是否存在。

`COUPLE_REQUIRED` 表示当前功能要求有效关系；`COUPLE_ACCESS_DENIED` 表示已有合法上下文但关系权限不允许该动作；`PRIVATE_RESOURCE` 表示已知资源的私密限制；`FILE_ACCESS_DENIED` 表示已知上传/访问凭证或文件操作未获授权。通过任意 ID 探测不属于自己的资源时统一返回 `RESOURCE_NOT_FOUND`，不能用 403 暴露其存在。列表、搜索和统计直接过滤无权内容。

`JOB_FAILED` 是需要报告任务执行失败时的稳定业务码。查询一个已授权但失败的任务本身仍返回 HTTP 200 成功包，任务字段中的 `error.code` 为 `JOB_FAILED`；只有端点操作本身因执行失败无法完成时才使用 HTTP 500 错误包。未分类内部异常统一为 `INTERNAL_ERROR`。

## 4. Bearer Token 与会话生命周期

除明确标注的注册、登录、验证码、刷新以及公开系统信息等端点外，用户接口必须发送 `Authorization: Bearer <accessToken>`。Access Token 为短有效期 JWT，后端验证签名、签发者、受众、有效期、账号状态和会话撤销状态，再建立用户上下文；不接受客户端传入的用户身份替代认证。

登录或注册成功返回 Access Token、Refresh Token 及对应有效期。Refresh Token 是仅用于刷新端点的高熵凭证，不作为 Bearer Access Token 使用，不放在 URL 中；移动端保存在系统安全存储中。服务端只保存 Refresh Token 摘要及会话、令牌族、到期和撤销信息。

刷新必须在事务内原子消费旧 Refresh Token 并签发下一对 Token，同一 Refresh Token 只能成功使用一次。发现已消费 Token 重放时撤销整个令牌族；已过期或撤销的刷新凭证返回 HTTP 401 `AUTH_REQUIRED`。客户端对并发 401 合并为一次刷新，等待刷新结果后再恢复请求；刷新失败时清除凭证并进入登录状态，不能无限递归刷新。刷新响应丢失时也不得无界重放旧凭证，必要时重新登录。

退出当前设备或指定设备撤销对应会话及令牌族；密码重置按安全流程撤销相关会话。账号禁用/注销状态即时阻断受保护调用。密码采用 Argon2id；验证码和 Refresh Token 只存摘要，日志不含密码、验证码、完整 Token 或完整手机号。验证码发送、登录和找回密码限流，敏感操作需再次校验密码或短信验证码。

## 5. 归属与可见性

数据归属从认证上下文和当前有效关系解析；请求中的 `userId`、`coupleId` 即使作为查询参数存在，也必须与权限范围重新匹配，不能直接信任。`PRIVATE` 仅创建者可见；`COUPLE` 仅资源所属当前有效情侣关系双方可见。不得预留公开、好友或指定用户等其他枚举。

权限判断覆盖详情、列表、搜索、聚合计数、伴侣回应、悄悄留言、引用内容、下载、缩略图和任务产物。复制进回忆册或提交生成任务不等于取得永久来源权限。关系解除、可见性变更、来源删除后，后续读取和产物访问重新校验；旧关系内容不能因用户建立新关系而共享给新伴侣。未到期胶囊正文和附件必须经过统一解锁校验。

## 6. 游标分页、过滤与排序

列表使用 `cursor` 和 `limit`；默认 `limit=20`，允许范围 1–100。首屏省略 `cursor`，后续原样提交 `meta.nextCursor`。游标是不透明且带完整性保护的字符串，绑定过滤、排序和授权范围，客户端不能解析或构造；参数变化后从首屏重新查询。无效或不匹配游标返回 HTTP 400 `VALIDATION_FAILED`。

```json
{
  "data": [
    {
      "id": "94f461f7-6af6-4d4f-8a7e-52f6beac5001",
      "createdAt": "2026-09-08T06:00:00.000Z"
    }
  ],
  "meta": { "nextCursor": "opaque_example_cursor", "hasMore": true },
  "requestId": "req_example_003"
}
```

末页为 `nextCursor: null`、`hasMore: false`；空列表为 `data: []`。一般列表默认按 `createdAt DESC, id DESC` 稳定排序，使用两字段共同作为游标边界。业务需要不同排序时必须在模块契约明确字段和同值时的 ID 次排序。读取期间的新数据或编辑可能改变列表，游标不承诺跨请求数据库快照；刷新从首屏开始。

过滤字段由各端点白名单定义，例如 `visibility`、日期范围和关键词；多个过滤条件按 AND 合并。统一用 `sortBy` 与 `sortOrder`（`asc`/`desc`）表达允许的排序。服务端验证字段与参数范围，参数化查询，禁止客户端传入 SQL 表达式。默认不返回总数；需要统计时仍使用相同权限过滤，不能泄露私密内容数量。

## 7. 幂等键与重复提交

创建情侣邀请、AI 任务、回忆册、支付订单和导出任务等关键创建操作使用 `Idempotency-Key` 请求头，具体必需端点由模块清单标注。客户端为一次用户意图生成随机 UUID；网络重试沿用同一键，用户发起新意图使用新键。缺少必需键或格式无效返回 `VALIDATION_FAILED`。

服务端以“认证用户 + HTTP 方法 + 规范化路由及资源参数 + 幂等键”为作用域，保存规范化业务请求摘要及执行记录；摘要不包含 Token、追踪 ID 等非业务请求头。首次请求通过数据库唯一约束占用键，并与业务写入、任务记录及权益预扣在同一事务中提交。Redis 不能作为防止重复扣费的唯一依据。

同键同载荷且已完成时返回首次业务结果及状态码，不再创建资源或扣费；当前 HTTP 尝试使用新的 `requestId`。返回缓存结果前仍校验当前账号、会话和资源权限，不能绕过关系解除或可见性变更。同键不同载荷返回 HTTP 409 `IDEMPOTENCY_CONFLICT`。同键尚在执行时也返回该错误，`details.reason` 为 `IN_PROGRESS`，客户端退避后用原键查询/重试，不能更换键重复创建。

幂等记录至少覆盖 24 小时，未结束的任务及未决账务不能因到达该时间被清除；模块可声明更长保留期。对于长期账务，业务唯一约束和账本关联还须阻止超出保留期的重复结算。事务提交前失败可安全使用原键重试；结果不明确时服务端先核对持久化记录，客户端先查询状态。外部调用不能与本地事务假定原子成功，按任务补投和补偿规则处理。

## 8. 乐观锁与事务

可被双方编辑的重要资源返回整数 `version`，初始为 1。更新和破坏性结构操作必须提交读到的 `version`，如修改共同记录、更新回忆册版面或调整页序。服务端在带授权条件的更新中同时匹配资源 ID 和版本，成功后原子执行 `version + 1`，返回最新资源；多表操作放在同一事务中。

版本不匹配返回 HTTP 409 `RESOURCE_VERSION_CONFLICT`，只能向已获授权调用者返回 `currentVersion`。客户端重新拉取资源，让用户核对或合并修改，再以新版本提交；不可自动强制覆盖。资源不存在或无权限时先按存在性保护规则处理，不能借版本错误泄露资源状态。页序调整作为一次整体更新校验回忆册版本，避免部分成功。

## 9. 文件上传握手与私密下载

文件二进制不进入通用 JSON 响应或 PostgreSQL，使用[文件与异步任务](./05-文件与异步任务.md)中定义的专用端点：

1. 客户端向 API 申请上传，提交文件用途、文件名、MIME、字节数及契约要求的摘要。API 校验身份、业务归属、额度和格式，创建待上传文件记录，生成对象键，返回 `fileId`、`uploadUrl`、`method`、`headers` 与 `expiresAt`，以及存储协议需要的受限表单字段。
2. 客户端仅向获准数据接口上传指定对象；上传方式、内容类型、大小和有效期受凭证限制。此时文件仍不可作为已完成素材读取或引用。
3. 客户端用 `fileId` 调用完成接口。后端再次检查归属，并通过存储适配器验证对象存在、实际大小、类型及适用的摘要；不能仅信任客户端声称上传成功。验证通过才登记为可用文件；失败或过期的对象进入清理流程。重复完成请求不得重复计入容量。
4. 读取私密文件时，API 校验资源、关系、可见性、删除及胶囊解锁状态后，签发短期访问地址。客户端不能指定完整对象存储路径或取得管理凭证。

直传对象存储的响应遵守存储协议；申请与完成等 API 请求仍使用统一成功/错误包。上传和下载签名 URL 视为短期凭证，不进入日志、通知正文或持久化分享地址。签名下载地址在到期前可能仍可使用，权限收回的最大暴露窗口由短有效期控制；需要即时收回的场景应由受控访问代理逐次鉴权。业务删除先标记并阻止新签名，由 Worker 幂等清理对象和衍生文件。

## 10. 异步响应与重试责任

长耗时 AI、视频、PDF、备份和批量清理请求返回 HTTP 202 及任务 ID，任务查询遵守同样的授权、响应与错误规范。任务记录是结果与进度的查询依据；客户端不能通过重复创建推进任务，也不能自行把任务标为成功或结算权益。

客户端仅对网络瞬断、429 以及可重试的服务端故障采用有上限的退避；写操作必须具有幂等保障，并先处理结果不明确的情况。业务校验、越权、额度和版本冲突不按技术故障自动重试。Worker 的重试次数、超时和失败补偿由统一任务契约定义；技术失败的预扣返还必须幂等且可审计。
