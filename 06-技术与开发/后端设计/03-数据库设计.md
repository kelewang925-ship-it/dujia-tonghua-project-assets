# 《独家童话》数据库设计

本文是 PostgreSQL + Prisma 的目标数据契约，与[总体架构](./01-总体架构.md)和[API 通用规范](./02-API通用规范.md)共同使用。API 与 Worker 在同一后端仓库维护同一套迁移；本资料不宣称已有数据库或可运行迁移。规划表严格限定为下列 54 张，Redis 键、Prisma 迁移历史和对象存储内部结构不计入业务表。

```text
users ──< user_sessions
users ──< couple_members >── couples
couples ──< records ──1 diary_entries / photo_sets ──< photo_items >── files
records ──< record_responses ──< response_attachments >── files
important_moments ──< moment_record_links >── records
couples ──< anniversaries / shared_reminders / time_capsules ──< time_capsule_items

memory_books ──< memory_book_chapters ──< memory_book_pages
memory_book_pages ──< memory_book_page_sources ──source── records / photo_items / important_moments / works
memory_book_pages ──< memory_book_supplements
users / couples ──< entitlement_grants >── subscriptions >── membership_plans
users / couples ──1 credit_wallets ──< credit_ledger >── async_jobs
```

七个现行非宠物模块是产品范围。`records` 统一承载日记与照片集合，详情分别由 `diary_entries`、`photo_sets` 扩展；伴侣回应和悄悄留言是私密双人反馈，回应依附 `records` 落在 `record_responses`，重要时刻通过 `moment_record_links` 连接表引用记录并聚合原始记录的回应，不另建讨论树。系统反馈工单只处理使用问题，不是社交举报。

## 2. ID、时间与金额

所有主键为 UUID；独立资源由服务端或数据库 `gen_random_uuid()` 生成，扩展表和一对一设置表复用父 UUID。UUID 对应 Prisma `String @db.Uuid`，表名/字段通过 `@@map`、`@map` 保持 snake_case。`timestamptz(3)` 对应 `DateTime @db.Timestamptz(3)`，所有数据库连接使用 UTC，API 输出带 Z 的 ISO 8601；`date` 是日历日期，`time(0)` 是当地墙上时间，必须结合明确的 IANA 时区解释。

金额使用 `bigint` 存最小货币单位，人民币单位为分；积分、字节数也用 `bigint` 且不含浮点数。API 中这些 bigint 字段用十进制字符串，避免 JavaScript 精度损失；比例和尺寸采用限定整数。各表写出的 varchar/char 长度是数据库上限，text 另有字符数 CHECK。

可变实体显式列出 `created_at`、`updated_at`，后者由数据库更新触发器写入事务当前时间，不仅依赖 Prisma `@updatedAt`。不可变事件、关联快照与账本只有 `created_at`；阅读状态有最近读取时间。每张表列出的字段是完整集合，不存在隐含公共列。`—` 表示没有默认值或没有额外约束，绝不表示未完成设计。可空列默认 `NULL`，必填但无默认值的列必须由受信任 Service 提供。

`version` 初值 1 且 CHECK ≥ 1。API 将客户端版本加入带归属条件的 UPDATE，成功原子加一。子表变更同时锁定并增加所属记录、草稿或回忆册的版本；多行调整不能逐行独立提交。

## 3. 归属、可见性与冻结

`owner_id` 是创建者；`couple_id` 是不可变的历史关系归属。带 `visibility` 的内容只允许 `PRIVATE/COUPLE`：前者只有创建者本人读取，后者要求请求者是该 couple 的当前有效成员。数据库基础 CHECK 为 `visibility IN ('PRIVATE', 'COUPLE') AND (visibility = 'PRIVATE' OR couple_id IS NOT NULL)`；带 couple 的创建者须是该关系成员，写入时用约束触发器验证。共享专属表的 couple_id 非空且不再放置多余 visibility 列。

关系激活必须在同一事务中锁定双方 users、邀请及 couples，写入两个不同用户的成员行。`slot` 只允许 1、2，未退出成员的 `(couple_id, slot)` 部分唯一索引限制每个有效关系最多两名；未退出成员的 user_id 部分唯一索引限制用户同时只能处于一个关系。延迟约束触发器在提交时保证 ACTIVE/DISSOLVING 关系恰有两个有效成员，DISSOLVED 关系没有有效成员，PENDING 最多一个有效成员。

解除关联在单次事务中将 couples 标记 DISSOLVED、写入 dissolved_at/frozen_at、结束双方成员关系、处理 dissolution 请求并撤销邀请。解除关联不得直接级联删除共同内容。冻结通过关系状态派生，不向每张共同内容表复制状态：旧 COUPLE 内容停止普通读取、修改、生成、导出和签发文件地址；旧关系私密内容仍仅允许其创建者读取和删除，涉及共同来源的派生产物仍受来源限制。不能把 couple_id 改成新关系，也不能将共同内容批量改为私密来绕过冻结。独立新内容使用新关系或空关系，恢复旧共同访问不是本期能力。

权限变化同时作废缓存、未投递预览与未完成生成；运行中的 Worker 写结果前重新校验关系和来源，失效时终止结果发布并按任务补偿。账号注销立即撤销访问，保留匿名用户占位主键支撑历史外键；共同内容不会随 users 或 couples 删除而级联清除。

## 4. 约束、事务与 Prisma 映射

字段中的 `FK → table.column` 均为真实 PostgreSQL 外键，默认 `ON DELETE RESTRICT ON UPDATE RESTRICT`；只有明确写出 SET NULL 的列采用该行为。复合 FK 的目标唯一键在父表列出，所有 FK 在迁移中建立可用 B-tree 索引；已被主键或唯一索引左前缀覆盖时不重复创建。CHECK、部分唯一索引、延迟约束触发器与权限无关的数据库不变量通过 Prisma migration SQL 定义并接受真实 PostgreSQL 集成测试；不伪装成 Prisma 能自动推导的规则。

全局 `G1` 为第三节的归属/可见性约束；`G2` 为 `updated_at >= created_at`、`deleted_at IS NULL OR deleted_at >= created_at` 与 version ≥ 1（只应用于实际存在的列）；`G3` 为外键指向的父内容、附件和来源归属相符。G3 的跨表检查由写入约束触发器完成，读取授权仍由 Guard、Service 和带过滤条件的 Repository 完成。触发器不能用 PostgreSQL CHECK 内的子查询代替。删除源对象前同时检查反向引用；所有业务物理清理都由受控 Worker 事务执行。

同一资源图写入先锁 couples，再锁用户/钱包，再按表名、UUID 稳定顺序锁父资源，避免绑定、清理和结算出现相反加锁顺序。不含 `deleted_at` 的排序连接表以各表实际父外键建立普通延迟 UNIQUE，页序重排事务提交时校验唯一性与父版本；例如 `memory_book_page_sources` 使用 `(page_id, position)`。Prisma schema 不能表达延迟属性，由 Prisma migration SQL 对实际表和列执行 `ALTER TABLE ... ADD CONSTRAINT ... UNIQUE (...) DEFERRABLE INITIALLY DEFERRED`，尖括号或通用列名不得原样进入 DDL。

带软删除且允许活跃行复用 position 的集合不能把部分唯一索引声明为 DEFERRABLE。三个目标表的实际映射固定为 `memory_book_chapters.book_id` → `memory_books.id`、`memory_book_pages.book_id` → `memory_books.id`、`memory_book_supplements.page_id` → `memory_book_pages.id`。章节与页面写事务先锁对应 memory_books 行，补页写事务先锁对应 memory_book_pages 行，再修改任意中间 position。Prisma migration SQL 分别创建 `AFTER INSERT OR UPDATE OF book_id, position, deleted_at ON memory_book_chapters`、`AFTER INSERT OR UPDATE OF book_id, position, deleted_at ON memory_book_pages`、`AFTER INSERT OR UPDATE OF page_id, position, deleted_at ON memory_book_supplements` 的 `CONSTRAINT TRIGGER ... DEFERRABLE INITIALLY DEFERRED`；各触发器函数按本表实际父外键查询 `deleted_at IS NULL` 的重复位置并抛出 `unique_violation`。父行锁串行化同一集合的并发写，延迟约束触发器保证事务最终态唯一；另建非唯一部分 B-tree 索引服务排序查询。稀疏非负 position 允许拖动排序，不以连续序号作为 ID。

`async_jobs` 同时承担可靠待投递记录和关键请求回执：`execution_mode=RECEIPT` 是同步创建的幂等回执，`execution_mode=QUEUED` 是 Worker 任务。占用认证用户、HTTP 方法、规范化路由含资源参数、幂等键的唯一作用域，与业务写入/预扣在一个事务提交。回执没有队列执行动作，不增加第五十五张业务表。`subscriptions` 一行代表一次开通/续费订单及其订阅期间，支付过程与结果也在该行持久化；每次续费新建一行，不覆盖已支付价格。

钱包余额只通过不可变流水变更：可用/冻结余额是不可变 `credit_ledger` 的缓存。仅受控入账函数能插入流水并锁定、更新钱包；API/Worker 普通数据库角色禁止直接写余额、更新/删除流水。RESERVE 将可用减 amount、冻结加 amount；SETTLE 将冻结减 amount；RELEASE 将冻结减 amount、可用加 amount；GRANT 只增加可用；ADJUST 只用于带审计理由的人工纠错。SETTLE 与 RELEASE 共用 origin_entry_id 唯一终结约束，不能同时终结同一预扣；重试任务沿用预扣，不能再次扣费。每日核对缓存与流水和，补偿也只能写新流水。

## 5. 通用 source 引用

`creation_draft_sources` 的 source_type 只允许 RECORD、PHOTO_ITEM、MOMENT；`memory_book_page_sources` 在同一机制上增加 WORK。`source_id` 是对应目标 UUID；RECORD → records.id，PHOTO_ITEM → photo_items.id，MOMENT → important_moments.id，WORK → works.id。自由回忆保存在草稿正文，原生补页保存在补页正文，不伪造成不存在的 source 表。

多态 source_id 不能声明一个指向四张表的普通 FK，因此迁移必须为每个引用表安装 INSERT/UPDATE 约束触发器，按封闭 source_type 分支验证目标存在、未软删除、同一关系、可见性和目标版本；为目标表安装删除保护触发器，存在引用时拒绝物理删除。Service 在插入前检查当前用户权限，提交时重新核验；更新来源可见性不会删除引用，而使其在读取时不可用。source_id/type 在提交的创作输入中不可改写。

复制摘要、截取照片、生成作品、页面预览和 PDF 都保留来源链。阅读、签名下载、搜索和导出递归验证来源；MOMENT 必须进一步检查其关联 records，WORK 必须检查其 ai_jobs → creation_drafts → sources。来源失效时只返回统一的不可用占位，不返回缓存正文或缩略图。布局中 source_ref 必须关联本页 source 行，生成快照不是权限凭证。草稿提交后冻结输入，修改须复制为新的草稿，保证既有作品来源链稳定。新增 source_type 必须先更新产品范围、映射和迁移；宠物接入明确越界，不设宠物表、字段或专用素材类型。

## 6. 删除、保留与敏感信息

保留时间以下列分级为设计默认值，部署策略可延长但不能提前抹除未决账务、活跃任务或引用依赖。`CONTENT`：软删除立即停读，30 天恢复窗口结束后解除子引用并排队清理；未删除内容持续保留，冻结关系共同内容持续冻结保留，不能由单方账户注销自动清除。`AUTH`：到期/撤销的会话在令牌族最后到期后保留 30 天用于重放核验；短信挑战到期 24 小时后清理，终态立即擦除摘要。`SECURITY`：安全与审计元数据保留 180 天，无正文。`FINANCE`：订单、权益、钱包和流水至少保留 5 年，未决争议或未结算引用阻止清理，此为工程保留基线而非法律结论。`JOB`：终态任务/事件保留 90 天，未终态及未结算无限延后；幂等回执至少 24 小时，关联业务终态和权益结清后才开始清理判断。`MESSAGE`：通知及投递终态保留 90 天。`CONFIG`：当前设置持续保留，账号匿名化清理；已生效协议、套餐和发布记录保留可追溯版本。

文件删除经 `async_jobs` 异步任务执行：业务软删除起拒绝新签名，恢复窗口内保留对象。清理 Worker 重新检查全部存活引用、生成任务和回忆册来源链；无引用且达到清理时间才删除原对象及 variants。S3 删除与数据库无法原子提交，先保留 DELETE_PENDING 元数据与 async_jobs 任务，对象删除可重试，确认不存在后写 DELETED/deleted_at。元数据最后保留 90 天，未释放引用前不能物理删除。上传暂存对象到期也走这一流程。副本/备份按独立生命周期过期，恢复后重新应用删除标记。

密码只存 Argon2id 哈希；Refresh Token、短信验证码、邀请码、设备标识、请求载荷和手机号检索值使用用途隔离的摘要/HMAC。可联系手机号、推送 Token、必要联系信息采用应用层信封加密，bytea 密文含算法版本与 key_id，密钥在部署密钥系统，数据库不保存明文密钥。文件二进制在私有对象存储；签名 URL、Access Token、验证码明文、完整手机号与供应商秘密从不写入数据库普通日志或审计。私密正文、输入快照和敏感元数据不进入业务日志，数据库备份同样加密与访问受控。

| `updated_at` | timestamptz(3) | 否 | now() | G2 | 修改时间 |

唯一约束：phone_digest 唯一，NULL 可重复；id 主键。检查约束：phone 三列同时有值或同时为空；非 ANONYMIZED 账号必须有手机号与密码；ANONYMIZED 必须清空手机号、密码、头像、生日、简介。索引：(status, created_at, id)、avatar_file_id。删除/保留：CONTENT；注销保留匿名主键以满足共同数据及 FINANCE 外键。敏感边界：手机号密文和密码哈希仅认证服务可读，不进入资料响应。

### `user_sessions`

一行表示令牌族中的一代 Refresh Token；family_id 为首代行 ID，也是设备会话对外 ID。

| 字段 | PostgreSQL 类型 | 空值 | 默认值 | 约束/外键 | 业务说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | uuid | 否 | gen_random_uuid() | PK | 令牌代次 ID |
| `user_id` | uuid | 否 | — | FK → users.id | 会话所属用户 |
| `family_id` | uuid | 否 | — | FK → user_sessions.id，延迟检查 | 稳定设备会话/令牌族 |
| `parent_token_id` | uuid | 是 | NULL | FK → user_sessions.id；UQ | 上一代令牌；首代为空 |
| `refresh_digest` | char(64) | 否 | — | UQ；十六进制摘要 | Refresh Token 摘要 |
| `device_digest` | char(64) | 否 | — | 十六进制 HMAC | 安装标识的摘要 |
| `device_name` | varchar(100) | 否 | — | — | 已过滤控制字符的设备展示名 |
| `platform` | varchar(12) | 否 | — | IOS/ANDROID/WEB | 登录平台 |
| `push_token_ciphertext` | bytea | 是 | NULL | 仅首代允许非空 | 设备推送 Token 信封 |
| `expires_at` | timestamptz(3) | 否 | — | 大于 created_at | 本代令牌有效期 |
| `consumed_at` | timestamptz(3) | 是 | NULL | — | 原子消费时间 |
| `revoked_at` | timestamptz(3) | 是 | NULL | — | 撤销时间；首代撤销阻断整族 |
| `last_seen_at` | timestamptz(3) | 否 | now() | — | 最近使用时间 |
| `created_at` | timestamptz(3) | 否 | now() | G2 | 签发时间 |
| `updated_at` | timestamptz(3) | 否 | now() | G2 | 消费或撤销时间 |
