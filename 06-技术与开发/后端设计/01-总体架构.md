# 《独家童话》后端总体架构

本文件定义目标后端的进程、领域与信任边界。产品范围遵守[后端设计入口](./README.md)，具体接口遵守[API 通用规范](./02-API通用规范.md)。这是后续工程的实施契约，当前资料仓库不包含已运行的后端服务。

## 1. 技术基线与产品边界

采用 Node.js 24 LTS、TypeScript、NestJS 模块化单体；通过 REST API 和 OpenAPI / Swagger 对接 Expo / React Native App。PostgreSQL 是唯一业务数据源，Prisma 负责数据库访问和版本化迁移，Redis 提供缓存、验证码摘要、限流和 BullMQ 队列，文件进入国内可部署的 S3 兼容对象存储。

产品来源仅为模块 01 账号登录、02 账号关联、03 首页与共同记录、04 重要时刻、05 童话工坊、06 我的与设置、08 共同回忆册。仅支持 `PRIVATE` 与 `COUPLE` 可见性；伴侣回应、悄悄留言为当前有效情侣关系内的私密双人交互。

本期排除情侣宠物及其 API、表、字段和专用素材类型，也排除好友、公开作品、公开评论及回复、动态、关注、社交广场、拉黑与举报。不增加额外可见范围。Supabase Auth、数据库、Data API、RLS、Storage、RPC、Edge Functions 全部退出目标架构；旧实现仅作迁移背景。

## 2. 部署拓扑

```text
Expo / React Native App
  | HTTPS REST /api/v1
  v
HTTPS 入口 / 反向代理
  |
  v
NestJS API（Docker，独立进程，可多副本）
  |-- Prisma --------------------> PostgreSQL（私网）
  |-- 缓存 / 限流 / 验证码摘要 ---> Redis（私网）
  |-- BullMQ 生产端 -------------> Redis 队列
  |-- 签发受限凭证 / 元数据校验 --> S3 兼容对象存储（私有桶）
  `-- 短信等同步调用 ------------> 供应商适配器
                                      |
Redis 队列 ---> NestJS Worker（Docker，独立进程，可多副本）
                 |-- Prisma -----> PostgreSQL
                 |-- 产物/清理 ---> S3 兼容对象存储
                 `-- AI / 媒体 / PDF / 推送等适配器

App -- 受限上传凭证 / 短期下载地址 --> 对象存储数据接口
```

API 与 Worker 位于同一后端代码仓库，共享领域代码、数据库访问和基础设施适配器，以独立入口启动、部署和扩容。API 不在 HTTP 请求内执行长耗时生成任务；Worker 不向 App 提供业务 HTTP 入口。两类进程可以使用同一版本镜像的不同启动命令，分别设置资源和并发限制。

PostgreSQL 与 Redis 均不暴露公网；仅允许后端私网身份和受控运维通道访问。App 不持有数据库凭证、Redis 凭证、对象存储管理权限或供应商密钥。对象存储直传只获得限定对象、方法、大小、类型和有效期的授权；私有桶不允许匿名列举或读取。

## 3. 十三个领域模块

| NestJS 模块 | 产品来源 | 数据与写操作职责 |
| --- | --- | --- |
| `auth` | 账号登录 | 手机注册、密码登录、短信校验、找回密码、Token 轮换、设备会话和撤销 |
| `users` | 账号登录、我的与设置 | 资料、头像、账号状态、注销申请与延迟清理协调 |
| `couples` | 账号关联、我们的小世界 | 邀请、确认、绑定、等待、情侣资料、解除关联及关系状态机 |
| `records` | 首页与共同记录 | 日记、照片、标签、可见范围、伴侣回应与共同记录搜索 |
| `moments` | 重要时刻 | 重要章节、纪念日、共同提醒、时光胶囊与悄悄留言索引 |
| `workshop` | 童话工坊 | 草稿、素材选择、主角设定、AI 创作请求、漫画及影片作品 |
| `memory-books` | 共同回忆册 | 书架、建册、通用素材引用、页面编排、章节页序、补页、阅读及管理 |
| `membership` | 童话会员 | 套餐、权益、情侣共享、AI 积分、容量额度及权益账务 |
| `settings` | 我的与设置 | 隐私、通知、显示及数据偏好，提供默认行为配置 |
| `files` | 多模块共享 | 上传凭证、元数据、访问签名、缩略图、引用与文件清理 |
| `notifications` | 重要时刻、工坊、设置 | 站内通知、已读状态、推送投递及通知偏好执行 |
| `jobs` | 工坊、回忆册、数据管理 | AI、视频、PDF、备份与清理任务的状态、重试和补偿 |
| `system` | 帮助与关于 | App 配置、协议版本、公告、版本检查与反馈 |

模块职责不机械对应页面。页面聚合查询可组合多个模块的只读结果；写入必须经拥有数据的领域 Service。Controller 负责协议转换和参数验证，Guard 建立认证与基础访问上下文，Service 校验业务权限和状态转换，Repository 负责带归属条件的查询及持久化。业务模块不得绕过其他模块的 Service 直接修改其数据。

共同回忆册引用来源内容时必须重新核验来源权限；工坊产物、导出、搜索、缩略图、通知预览均继承相应内容限制。通用素材引用不成为重新引入排除模块的入口。

## 4. 权限与一致性

用户身份来自校验后的 Access Token 和有效会话；情侣归属从数据库当前有效关系解析。客户端提交的 `userId`、`coupleId` 不能作为授权依据。Repository 必须携带用户/情侣归属、可见性和删除状态条件，禁止仅按资源 ID 读取后遗漏权限判断。

`PRIVATE` 只允许创建者访问；`COUPLE` 必须匹配资源所属关系且请求者仍是该关系的有效成员。旧关系数据不自动迁移给新伴侣。解除关联不直接级联删除共同日记、照片、时刻、作品和回忆册；保留与清理由生命周期流程处理。未到期胶囊的正文及附件在所有读取渠道均受解锁规则限制。

跨表业务状态转换使用 PostgreSQL 事务；唯一约束、外键和乐观锁与 Service 校验共同防止并发错误。Redis 缓存及队列均不是额度、关系或任务结果的最终事实来源，缓存缺失时回源数据库，权限变化时失效相关缓存。

创建异步任务时，业务记录、任务记录和额度预扣原子写入数据库。数据库提交和 BullMQ 入队不能视为同一事务：采用数据库中的待投递任务记录作为可靠投递依据，提交后投递，并由扫描补投修复入队失败；投递使用稳定任务 ID 去重。Worker 仍须通过数据库状态检查和原子转换保证重复执行不会重复结算。任务终态、重试、超时和补偿详见[文件与异步任务](./05-文件与异步任务.md)。

## 5. 供应商适配器边界

| 适配器 | 对领域暴露的能力 | 隔离内容 |
| --- | --- | --- |
| 对象存储 | 签发上传、检查对象、短期访问、删除 | S3 SDK、桶配置、签名格式与存储异常 |
| 短信 | 发送指定用途的验证码消息、返回投递结果 | SDK、模板映射、供应商回执和凭证 |
| 推送 | 按设备投递通知、报告投递状态 | 平台推送协议、设备凭证和原始错误 |
| AI 生成 | 提交生成、查询或接收结果、规范化产物与失败 | 模型参数转换、供应商任务 ID、鉴权与原始响应 |
| 媒体与导出 | 图片/视频处理、PDF 和备份产物生成 | 编解码工具、渲染实现和临时文件策略 |

供应商 SDK 仅存在于基础设施适配器。领域 Service 依赖类型化接口并接收统一结果，不存取云厂商凭证，也不向 App 透传供应商异常。适配器负责超时和协议转换；涉及计费或有副作用的调用，其重试必须服从任务幂等与结算规则。供应商回调先验签、去重并关联内部任务，再进入领域状态机。

## 6. 环境、配置与密钥管理

划分本地开发、自动化测试、预发布、生产四种环境。各环境独立数据库、Redis 命名空间或实例、对象存储桶与凭证；生产与非生产基础设施及密钥隔离。测试使用合成用户及文件，不能复制真实用户内容到开发环境。

普通配置包括服务端口、环境标识、超时、并发和功能开关；由结构化配置模块在启动时校验类型及必填项。密钥通过部署平台密钥管理注入，仓库仅保留不含真实值的配置说明。API 和 Worker 使用最小权限身份；迁移使用专门部署身份，不让普通请求持有 DDL 权限。

密码采用 Argon2id 哈希；Refresh Token 和短信验证码只保存摘要。JWT 签名密钥、短信、推送、AI、数据库和存储凭证支持独立轮换。访问有效期、风控阈值、供应商内部配置与密钥值不写入公开页面。缺少关键配置时进程启动失败，不能静默降级到不安全配置。

数据库迁移由部署流程单点执行，先验证备份及回滚/前向修复方案，再发布兼容的 API 和 Worker；多副本不能在启动时竞争执行迁移。滚动发布期间保留任务载荷版本兼容性，Worker 优雅关闭时停止拉取新任务并处理或安全释放进行中的任务。

## 7. 日志、审计与运行保障

结构化日志携带 `requestId`，异步链路关联内部 `jobId` 和原始请求追踪信息。记录路由模板、状态码、耗时和稳定错误码；审计关注登录、会话撤销、关系变更、额度结算、文件访问授权及注销状态转换。

日志脱敏必须覆盖密码、验证码、完整 Token、完整手机号、签名 URL 查询串与凭证。默认不记录请求/响应正文、私密日记、留言、胶囊内容、AI 输入和生成文件。异常日志不得将 SQL 参数、用户正文或供应商原始响应混入公开错误信息。审计记录受访问控制和保留策略管理。

监控 HTTP 延迟与错误、数据库连接和慢查询、Redis 可用性、队列积压、任务失败与重试、文件清理滞留及预扣未结算情况。API 提供存活与就绪检查；Worker 提供受控运行状态观测。Redis 队列持久化配合数据库补投，数据库定期备份并演练恢复，对象存储配置版本/生命周期策略；恢复后核对任务终态与权益账务。

## 8. 未来拆分条件

第一版保持模块化单体。优先单独扩容 Worker 或按队列划分 Worker 进程；只有监控证明某领域具有持续独立负载、资源隔离或发布需求，且边界已稳定、团队具备跨服务运维能力时，才评估服务拆分。

拆分前必须明确数据所有权、跨边界事务替代方式、事件可靠投递、幂等、版本兼容、追踪、故障恢复和容量指标，并记录收益及成本。不能只为页面数量或供应商数量增加微服务。新增产品能力仍需先更新范围规格，再设计接口和数据。
