# 《独家童话》后端设计资料

本目录是《独家童话》目标后端的权威设计入口。这里的文档共同定义后端架构、REST API、PostgreSQL 数据模型、文件与异步任务流程，以及分阶段实施门槛；它们用于指导后续后端工程建设，不代表本仓库已经包含可运行的后端服务。

## 范围

产品事实以 `新模块分布/` 中七个现行非宠物模块为准：

1. 模块 01：账号登录；
2. 模块 02：账号关联；
3. 模块 03：首页与共同记录；
4. 模块 04：重要时刻；
5. 模块 05：童话工坊；
6. 模块 06：我的与设置；
7. 模块 08：共同回忆册。

后端按领域职责组织，而不是机械复制页面目录。情侣内部的伴侣回应与悄悄留言属于私密双人交互，仅服务当前有效情侣关系。

## 明确排除

本期不设计或实现情侣宠物、好友关系、好友作品可见性、公开评论及回复、公开动态、关注、社交广场、拉黑和举报。共同回忆册可以保留通用素材引用能力，但不得因此建立宠物 API、数据表、字段或专用素材类型。

Supabase Auth、数据库、Data API、RLS、Storage、RPC 和 Edge Functions 均不属于目标架构。旧 Supabase 代码与资料只可作为迁移历史，不能作为新后端实现依据。

## 技术基线

- 运行时与语言：Node.js 24 LTS、TypeScript；
- Web 框架：NestJS，采用模块化单体与独立 Worker，不拆分微服务；
- 接口契约：REST API 与 OpenAPI / Swagger，基础路径为 `/api/v1`；
- 数据设施：PostgreSQL、Prisma、Redis、BullMQ；
- 文件设施：国内可部署的 S3 兼容对象存储；
- 认证：手机号、短信验证码、密码、JWT Access Token 与轮换式 Refresh Token；
- 部署：Docker，API 与 Worker 作为可独立启动、扩容和部署的进程。

## 维护规则

1. 产品事实变化时先核对现行设计稿，再同步修改受影响的架构、API、数据库和实施文档，避免单点更新。
2. 新接口必须遵守通用 API 契约，并能追踪到数据表、权限规则、事务边界和测试要求。
3. 新数据表或字段必须记录类型、空值、默认值、约束、索引、归属和删除策略，不以模糊占位语代替设计。
4. 供应商名称、密钥、内部配置、真实用户信息和本机绝对路径不得写入公开资料。
5. 每次修改后运行 `node scripts/test-backend-docs.mjs`；测试清单中的文档必须存在、非空且包含一级标题。
6. 任何新增范围都必须先更新权威规格；废弃范围不得以预留接口、数据表或枚举值重新进入目标架构。
