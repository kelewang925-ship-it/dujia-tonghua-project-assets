# 《独家童话》后端资料与公开页面实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在项目资料仓库中建立七个现行非宠物模块的 Node/NestJS 后端架构、完整 REST API、PostgreSQL 表字段、开发路线和公开可浏览页面。

**Architecture:** 资料以六份职责单一的 Markdown 文档为开发基准，`backend-design.html` 提供面向浏览者的静态交互视图，现有 GitHub Pages 首页负责入口导航。Node 测试和 PowerShell 公开文件校验共同保证范围、链接、API/表条目、敏感信息和发布清单一致。

**Tech Stack:** Markdown、HTML5、CSS、原生 JavaScript、Node.js 测试脚本、PowerShell、GitHub Pages

**Spec:** `06-技术与开发/后端设计/2026-09-08-Node后端架构与API数据设计规格.md`

## Global Constraints

- 只修改当前资料仓库根目录，不修改 Expo App 仓库。
- 产品范围只来自 `新模块分布/` 下模块 01、02、03、04、05、06、08 的现行根层页面与模块记录。
- 完全排除 Supabase 生产架构、宠物、好友、公开作品权限、公开评论、拉黑和举报。
- 目标后端固定为 Node.js 24 LTS、TypeScript、NestJS、REST/OpenAPI、PostgreSQL、Prisma、Redis、BullMQ、国内 S3 兼容对象存储和 Docker。
- 架构固定为模块化单体加独立 Worker，不拆微服务。
- 第一版认证固定为手机号、短信验证码、密码、JWT Access Token 和轮换式 Refresh Token。
- API 使用 `/api/v1`、JSON `camelCase`、数据库 `snake_case`、UUID、UTC/ISO 8601、游标分页、稳定业务错误码、幂等键和乐观锁。
- 公开页面不能包含密钥、内部供应商配置、真实手机号、本机绝对路径或废弃功能的业务接口。
- 本计划不创建 NestJS 工程、不执行数据库迁移、不改造 App API，也不删除任何分支。
