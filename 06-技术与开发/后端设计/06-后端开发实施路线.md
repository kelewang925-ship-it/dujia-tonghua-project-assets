# 《独家童话》后端开发实施路线

本路线以[总体架构](./01-总体架构.md)、[API 通用规范](./02-API通用规范.md)、[数据库设计](./03-数据库设计.md)、[模块 API 清单](./04-模块API清单.md)和[文件与异步任务](./05-文件与异步任务.md)为唯一实现依据。先搭 NestJS 后端再逐模块替换客户端：先完成 NestJS API 与独立 Worker，再按已验收模块逐步替换客户端；151 个 API、54 张表和既有枚举是封闭契约，任何扩展先更新这五份资料并通过评审。

当前 App 代码不改；本资料任务不修改 Expo、React Native、Mock 或 Supabase 调用。旧 Supabase 分支暂留，且由用户后续手删；不以清理历史分支作为后端阶段的交付项。客户端迁移完全验收后，最终完全移除 Supabase Auth、数据库、Data API、RLS、Storage 和 Edge Functions，且先完成可恢复的数据迁移和生产验收，绝不以“双写常态化”取代收口。

大陆部署、对象存储、短信、推送、AI 与观测供应商均必须可替换：NestJS 领域模块只依赖适配器接口和统一的错误/指标模型。v1 不做情侣宠物、好友、公开评论或回复、公开作品、动态、关注、拉黑、举报和任何陌生人社交能力；它们不进入迁移、DTO、队列、测试数据或客户端切换。

## 共同执行规则

- 每阶段先写该阶段的单元/集成/端到端失败用例，确认 RED，再实现最小服务、迁移和适配器，确认 GREEN；阶段门禁未通过不能开启依赖它的写路径。
- 所有数据库变更用 Prisma migration 加必要的 PostgreSQL SQL（延迟约束触发器等），在影子库、真实 PostgreSQL 测试库、预发布备份恢复演练后才生产执行。已含数据的生产迁移采用扩展、回填、切换、收缩；失败优先前向修复，禁止在生产直接回滚会损失数据的 DDL。
- API 与 Worker 同仓而独立进程、独立部署/扩缩容；PostgreSQL 是业务事实，Redis/BullMQ 只作缓存和投递。队列任务以 `async_jobs` 可靠补投，文件以 authorize→PUT→complete 和来源链授权，积分以 RESERVE→SETTLE/RELEASE 结算。
- 每阶段发布使用兼容 API/任务载荷、功能开关、请求追踪、数据库备份与回滚演练。退出条件不是“代码已合并”，而是完成标准、监控和反向安全用例同时成立。

## 阶段 0：工程基础

### 目标

建立可重复的 NestJS 模块化单体、独立 Worker、Prisma/PostgreSQL、Redis/BullMQ、Docker、OpenAPI、配置和测试底座；不承载任何已发布业务能力。

### 产物

同仓 API/Worker 启动命令、模块骨架、配置校验、统一 `{data,meta,requestId}`/稳定错误包、JWT Guard 占位、结构化脱敏日志、health/readiness、Prisma migration 管线、OpenAPI 骨架、Docker Compose（本地）和 CI 的真实 PostgreSQL/Redis 服务。

### 前置依赖

已批准的五份后端资料、Node.js 24 LTS、TypeScript、NestJS、Prisma、PostgreSQL、Redis、BullMQ，以及不含真实密钥的环境变量样例；生产密钥管理、私网网络和备份账户由部署环境提供。

### NestJS 模块

`config`、`database`、`cache`、`queue`、`observability`、`http`、`auth` Guard 基础、`files`/`jobs` 适配器接口和 API/Worker 两个 bootstrap；不接入业务 Controller。

### API

仅内部存活/就绪探针与 Swagger 文档构建验证；不把内部运维路由加入 `/api/v1` 业务目录，不对 App 发布业务端点。

### 数据表

无业务写路径。建立迁移目录、UUID/时间/审计/软删约束公共 SQL 和 54 表的依赖清单，确保随后每张表只能按已批准字段字典落地。

### 迁移

在空的影子库验证迁移顺序、锁等待和 Prisma migration SQL；建立生产迁移前备份、版本记录和前向修复模板。此阶段不导入旧 Supabase 数据、不创建 Supabase 兼容层。

### 单元测试

配置缺失即启动失败、requestId 生成、错误包脱敏、日志不写凭证、适配器接口替换、API/Worker 不共享 HTTP 监听器。

### 集成测试

真实 PostgreSQL 和 Redis 连接、迁移可从空库重复执行、BullMQ 命名空间隔离、Docker 网络不暴露数据库/Redis 公网端口。

### 端到端测试

容器化 API/Worker 启停、存活/就绪探针、Swagger 生成和 CI 从干净环境运行；无密钥时失败而非静默降级。

### 运维验证

检查环境隔离、秘密注入、结构化日志收集、基础指标、备份任务和告警通道；确认大陆部署网络可连接可替换的适配器而不固化供应商 SDK。

### 完成标准

API 与 Worker 可独立启动，测试库迁移和 CI 可重复运行，统一协议/追踪/脱敏/就绪检查全绿，且没有业务端点绕过 Guard 或直接依赖供应商。

### 本阶段不做事项

不实现认证、文件、队列业务、App 改造、数据迁移或任何 v1 排除能力。

### 回滚/退出

仅删除非生产测试容器和空影子库；已发布镜像回退到上一个兼容镜像。生产迁移失败停止发布并以前向修复/从验证过的备份恢复，保留审计记录后才能进入阶段 1。

## 阶段 1：账号与用户

### 目标

交付手机注册、登录、密码/短信找回、JWT Access Token、Refresh Token 轮换、设备会话、本人资料、敏感操作再认证与账户注销申请入口。

### 产物

`auth` 和 `users` Service、Argon2id 密码实现、短信适配器、会话/令牌族 Guard、限流、审计、安全事件、用户资料 DTO 与账户注销状态机的 API 读写路径。

### 前置依赖

阶段 0 的配置/数据库/HTTP 基座；短信沙箱和生产适配器的用途模板、JWT 密钥轮换策略、加密密钥及账号风控阈值由受控配置提供。

### NestJS 模块

`auth`、`users`、`settings` 的默认配置创建、`membership` 的零余额钱包创建接口，以及 `system` 的协议文档授权读取；不启用情侣或消费业务。

### API

实现 `/auth/sms-codes`、`/auth/register`、`/auth/login`、`/auth/token/refresh`、`/auth/logout`、密码重置、会话列表/撤销和 `/users/me`、头像占位授权、密码变更、注销申请/查询/撤回，严格遵循 API 清单的阶段 1 标记。

### 数据表

`users`、`user_sessions`、`sms_challenges`、`account_security_events`、`account_deletion_requests`、`user_settings`、`privacy_settings`、`notification_preferences`、`credit_wallets`、`audit_logs`；为钱包外键先建立空的 `couples`/`couple_members` 结构但不开放阶段 2 业务写入。

### 迁移

先创建用户/会话/安全/默认设置与钱包表、手机号唯一和令牌摘要约束，再创建仅供后续外键使用的情侣结构；注册事务同时建立零余额钱包。生产从旧身份迁移前先做哈希/令牌不可逆性评估，不能搬运旧明文凭证。

### 单元测试

验证码单次消费、Argon2id 校验、刷新重放撤销令牌族、账号锁定、注销令牌只能管理注销、资料字段白名单和所有敏感日志脱敏。

### 集成测试

并发刷新只有一个成功、手机号唯一、会话撤销立即阻断 Guard、注册事务包含默认设置和零余额钱包、短信失败不泄露账号存在。

### 端到端测试

注册/登录/刷新/退出/找回/会话撤销的成功与错误码路径；错误密码、失效验证码、无效 Bearer、被撤销会话和越权用户资料均为规定响应。

### 运维验证

验证短信适配器切换、发送和登录限流、密钥轮换、账号安全审计、认证失败告警和恢复演练，不记录完整手机号、验证码或 Token。

### 完成标准

所有身份反向测试通过，认证用户无法跨用户访问，Refresh Token 不能作为 Bearer，注销申请有可追踪状态且尚不清理共同内容。

### 本阶段不做事项

不开放情侣邀请、记录、文件完成、积分消费、支付、客户端 Supabase 切换或第三方登录。

### 回滚/退出

认证端点先灰度且保留上一个兼容 API 镜像；发现安全/会话错误立即关开关、撤销新令牌族并回到既有登录入口。不可逆账号数据迁移失败从演练验证的备份恢复，不删除用户审计。

## 阶段 2：情侣关系

### 目标

实现邀请、双向确认、绑定、等待、过期/撤销、情侣资料和解除关联状态机，保持历史共同内容不被级联删除。

### 产物

`couples` Guard/Service、邀请代码安全处理、PENDING/ACTIVE/DISSOLVING/DISSOLVED 状态转换、并发锁顺序、解除任务登记和关系权限查询接口。

### 前置依赖

阶段 1 的有效会话、用户资料、审计和空情侣结构；阶段 0 的事务、乐观锁、限流及 Worker 可靠投递基础。

### NestJS 模块

`couples` 为所有者，协作 `auth`、`users`、`jobs`、`notifications`；普通内容模块仍未开放写入。

### API

实现 `/couples/current`、成员/资料、邀请创建/查询/撤销/接受/确认及当前解除申请的创建、查询、确认、撤回，严格按 API 清单阶段 2 路径和两种 ACTIVE/DISSOLVING Guard 区分。

### 数据表

`couples`、`couple_members`、`couple_invitations`、`couple_dissolutions`、`async_jobs`、`audit_logs`，并读取 `users`、`user_sessions` 与通知偏好；不写未实施内容表。

### 迁移

补齐最多两名有效成员、一个用户最多一个有效关系、邀请码摘要/到期、解除任务反向引用、历史关系保留与锁/索引约束；迁移后以数据库约束而非仅 Service 阻止双重关系。

### 单元测试

邀请者/受邀者最小资料输出、邀请码明码只首次响应、双方竞争 PENDING 邀请合并、解除中 Guard 仅允许三个生命周期端点、旧关系不迁移给新关系。

### 集成测试

并发接受同一邀请码、双方各自创建邀请后接受/确认、唯一约束冲突、锁顺序、撤销与确认互斥、关联解除不级联共同内容。

### 端到端测试

非成员探测为 404、ACTIVE 成员才可普通共同写、DISSOLVING 成员只能走专用解除端点、关系更新的 version 冲突和邀请过期/取消全覆盖。

### 运维验证

观察关系状态转移、冲突率、解除任务积压和审计链；演练 API/Worker 重启时待投递解除任务的可靠补投。

### 完成标准

任何并发路径都不会产生重复有效关系，解除冻结而不误删历史共同内容，等待状态不泄露电话、生日或简介。

### 本阶段不做事项

不开放记录、文件签名、时刻、AI、回忆册或任何 v1 排除的社交关系。

### 回滚/退出

发现关系一致性异常立即关闭邀请和确认写开关，保留只读与审计，使用事务性前向修复处理孤立 PENDING；不删除历史 couples/couple_members 行。

## 阶段 3：文件与共同记录

### 目标

交付私有文件 authorize→PUT→complete、签名下载、延迟删除、日记、照片集、标签、伴侣回应和搜索，且 PRIVATE 内容不经任何读取入口泄露。

### 产物

`files`/存储适配器、上传会话、checksum/MIME/容量校验、来源链签名授权、FILE_DELETE/FILE_VARIANT Worker、`records` Service、游标搜索和文件引用计数事务。

### 前置依赖

阶段 1 的身份与钱包、阶段 2 的 ACTIVE 情侣 Guard、阶段 0 的对象存储/队列适配器和阶段 2 的可靠任务投递。

### NestJS 模块

`files`、`records`、`jobs`、`couples` 授权查询、`membership` 容量校验、`notifications` 的回应触发；Worker 独立处理清理和变体。

### API

实现 `/files/storage-usage`、上传会话创建/complete/取消、下载地址、文件删除；实现 `/records/home`、记录/日记/照片集、照片排序、标签、回应、收件箱和搜索的全部阶段 3 API。

### 数据表

`files`、`file_upload_sessions`、`file_variants`、`async_jobs`、`records`、`diary_entries`、`photo_sets`、`photo_items`、`tags`、`record_tags`、`record_responses`、`response_attachments`、`notifications`、`notification_deliveries`，并读取用户、关系、钱包与设置表。

### 迁移

创建对象键唯一、上传凭证摘要、文件/会话/变体状态与引用约束，建立记录归属/可见性/排序/搜索索引；加入文件 DELETE_PENDING 与 async_jobs 的反向唯一约束。先在合成对象桶验证生命周期，生产不导入无校验的旧 Storage 对象。

### 单元测试

服务端对象键生成、伪造大小/MIME/checksum 拒绝、complete 幂等、取消/过期互斥、直接引用增减、来源链递归、PRIVATE/COUPLE 判断、文件删除前变体重查。

### 集成测试

真实对象存储替身的受限 PUT、并发容量预留、事务内照片顺序/标签/回应、FILE_DELETE 对已不存在对象幂等、BullMQ 重复消息不重复清理。

### 端到端测试

上传后才 READY、非 owner 不能 complete、错误 resourceType/resourceId/fileId 不能签名、PRIVATE 记录不会出现在伴侣列表/搜索/回应/附件、版本冲突不部分写入。

### 运维验证

监控上传/complete 拒绝、隔离对象、对象存储延迟、无主对象、清理滞留、签名拒绝率和队列积压；演练对象存储适配器替换与受控访问代理即时撤销。

### 完成标准

所有文件只有经服务器验证后才 READY，签名完整复核真实引用与来源链，恢复窗口与删除任务不会误删有引用对象，记录权限反向测试全绿。

### 本阶段不做事项

不开放时刻/胶囊、AI 生成、支付、导出、回忆册或任何公开内容能力。

### 回滚/退出

文件和记录写入口按功能开关停用，已签发地址自然短期过期；失败迁移前向修复，保留 `UPLOADING`/`DELETE_PENDING` 记录由 Worker 收敛，绝不批量删除对象桶。

## 阶段 4：重要时刻

### 目标

实现重要章节、记录关联、纪念日、共同提醒、时光胶囊和私密悄悄留言索引，保证未到期胶囊在所有渠道不可读取。

### 产物

`moments` Service、时间/时区计算、提醒调度、胶囊锁定 Guard、来源可用性占位和安全通知编排。

### 前置依赖

阶段 1 身份/设置、阶段 2 当前关系、阶段 3 记录/文件/签名与 `async_jobs`/通知基础。

### NestJS 模块

`moments`、`records` 来源授权、`files`、`notifications`、`settings`、`jobs`；不在 Controller 绕过 records/moments 所有者查询。

### API

实现 `/moments` 及记录链接、`/anniversaries` 和 countdown、`/reminders` 已读、`/time-capsules`、胶囊 items/seal/open 的全部阶段 4 API。

### 数据表

`important_moments`、`moment_record_links`、`anniversaries`、`shared_reminders`、`time_capsules`、`time_capsule_items`、`notifications`、`notification_deliveries`、`async_jobs`，读取 records/files/settings/couples。

### 迁移

创建时刻-记录链接、纪念日时区/重复规则、提醒接收者唯一、胶囊解锁/项目顺序/文件用途约束和来源删除保护；到期调度使用既有任务表，不新增提醒队列表。

### 单元测试

闰日/时区倒计时、PRIVATE 来源不能关联共同时刻、胶囊 seal/open 状态机、未到期正文/附件/缩略图拦截、提醒只可由接收者标已读。

### 集成测试

来源收窄或删除后时刻封面和摘要失效、同一 occurrence 通知去重、胶囊到期任务重复执行、解除关系后共同提醒停止投递。

### 端到端测试

所有时刻、胶囊、提醒 API 的认证/情侣/版本/文件上下文检查；未到期胶囊经详情、文件、导出候选、缩略图均不暴露内容。

### 运维验证

核对时区调度延迟、错过任务补扫、提醒队列失败、封存内容日志脱敏和来源失效指标。

### 完成标准

提醒与悄悄留言不混为同一实体，胶囊时间门槛覆盖每个读取与派生入口，来源失效不会保留旧缓存正文。

### 本阶段不做事项

不实现 AI、会员结算、回忆册、支付或面向陌生人的消息/评论功能。

### 回滚/退出

停用新建/封存/提醒写入口并让既有安全只读保持；调度异常以持久 `async_jobs` 补投恢复，不手动修改胶囊解锁时间或删除共同内容。

## 阶段 5：童话工坊与权益

### 目标

交付创作草稿、来源选择、主角设定、套餐/权益、AI 积分预扣结算、AI Worker、作品、资产和私密通知。

### 产物

`workshop`、`membership`、`jobs` Service，AI/支付/推送适配器，`ai_jobs` 与 `async_jobs` 双层任务、事件进度、RESERVE/SETTLE/RELEASE 账本和作品私有产物流程。

### 前置依赖

阶段 1 钱包、阶段 2 关系、阶段 3 文件和来源签名、阶段 4 时刻来源；阶段 0 的独立 Worker、可靠补投、DLQ 和观测必须已验收。

### NestJS 模块

`workshop`、`membership`、`jobs`、`files`、`notifications`，并调用 records/moments/couples 的授权 Service；AI/支付供应商只在适配器层。

### API

实现 workshop 概览/素材/草稿/主角、`/ai-jobs` 创建/查询/取消/重试、作品列表/详情/删除/保存相册/通知伴侣、会员 plans/me/orders/credits/ledger 的阶段 5 API。

### 数据表

复核全部 54 张表、索引、约束、账本、来源链、任务和保留策略；只允许为已批准字段的兼容回填/索引优化做迁移，不增加未定义业务实体。

### 单元测试

### 集成测试

真实 PostgreSQL 并发/死锁、Redis/BullMQ 宕机与可靠补投、对象存储/短信/观测供应商切换、备份恢复、迁移校验和容量/限流边界。

### 端到端测试

全部 151 接口的认证、越权、重放、重复提交、版本冲突、失败补偿、文件/导出泄露、客户端灰度/回退以及账号注销完整链路；当前用户与非关系成员的反向访问矩阵必须全绿。

### 运维验证

压测 API/Worker 分别扩缩容，演练区域/对象存储故障、DLQ 堆积、告警升级、灾难恢复和发布回滚；上线观察错误预算、队列年龄、签名拒绝、预扣未结算、账本差异和数据核对。

### 完成标准

所有安全、并发、恢复和性能门禁通过；每个客户端迁移波可独立回退；生产读写、身份、文件、队列和观测均不再调用 Supabase，数据迁移核对与退役证据完整。

### 本阶段不做事项

不在加固期夹带新功能、不扩展 v1 范围、不删除旧分支，也不把供应商配置或密钥公开到 App/资料页。

### 回滚/退出

任一灰度指标越界即停止下一波、关闭对应客户端后端开关并回到上一已验证读写路径；保留 Supabase 只读核对直到所有退出门禁完成。最终退役后仅从 PostgreSQL/私有对象存储的已验证备份恢复，退役操作由用户授权的发布流程执行。

## 客户端替换与 Supabase 退役判定

后端不是把现有 App 原地重写的前置条件：先用契约测试和受控工具验证 NestJS，再按阶段 8 的模块顺序替换客户端。每一模块需要证明登录态迁移、错误展示、幂等重试、文件上传、离线恢复和回退路径；一个模块未达标不扩大切换范围。切换期间避免长期双写：需要迁移时采用可审计的单向批次和只读核对，业务事实始终有一个权威写源。

只有当 App 发布版本不再包含 Supabase 客户端调用、运行配置/密钥/边缘函数引用全部移除、PostgreSQL/对象存储数据核对完成、后台 Worker 无 Supabase 依赖、回退窗口关闭且保留/审计义务满足时，才可声明最终完全移除 Supabase。旧 Supabase 分支和历史资料按开头约定暂留，不属于本路线自动删除对象。
