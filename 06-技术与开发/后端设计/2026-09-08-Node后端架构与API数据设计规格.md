# 《独家童话》Node 后端架构与 API / 数据设计规格

更新时间：2026-09-08

状态：已完成方案确认，等待书面规格审阅
适用范围：`新模块分布/` 下除模块 07「情侣宠物」外的七个现行模块

## 一、目标

本规格定义《独家童话》后端、API、数据库和公开设计查看页的建设边界，为后续开发提供唯一、可执行的技术基准。

本阶段只修改项目资料仓库，不修改现有 Expo App 代码，不删除或调整 App 仓库中的任何分支。后续 App 接入应以本规格产生的 REST API 契约为目标，逐步替换现有 Mock 与 Supabase 相关实现。

最终生产架构完全移除 Supabase，包括 Supabase Auth、数据库、Data API、RLS、Storage 和 Edge Functions。Supabase 历史代码与历史文档只作为迁移背景，不作为新后端的实现依据。

## 二、产品范围

### 2.1 当前唯一产品依据

产品功能以 `新模块分布/` 下的现行设计稿及各模块的 `设计与生成记录.md` 为唯一基准：

1. 模块 01：账号登录
2. 模块 02：账号关联
3. 模块 03：首页与共同记录
4. 模块 04：重要时刻
5. 模块 05：童话工坊
6. 模块 06：我的与设置
7. 模块 08：共同回忆册

`02-产品与功能/`、旧九模块、旧 67/69 页计划、历史未通过设计稿和现有 App 路由只能用于了解历史背景，不得覆盖最新模块定义。

### 2.2 明确排除

以下能力不进入本次 API、数据表或公开设计页：

- 情侣宠物模块的全部功能；
- 好友关系；
- 好友作品可见性；
- 公开评论与评论回复；
- 拉黑与举报；
- 公开动态、关注、社交广场或陌生人内容；
- Supabase 专有实现、RLS policy、RPC 或 Edge Functions。

共同回忆册中的“作品与宠物成长页编排”只保留可扩展的素材引用能力。本期可以引用工坊作品，但不创建宠物 API、宠物表、宠物字段或宠物专用素材类型；未来宠物模块有独立设计后再接入。

### 2.3 私密双人交互定义

“伴侣回应”和“悄悄留言”是情侣内部针对共同记录或重要时刻的私密回应，不是公开评论系统。它们只允许当前有效情侣关系的双方访问。

内容可见范围只包含：

- `PRIVATE`：仅创建者本人可见；
- `COUPLE`：当前有效情侣关系双方可见。

不预留好友、公开或指定用户可见范围。

## 三、总体技术架构

### 3.1 技术基线

- 运行时：Node.js 24 LTS
- 语言：TypeScript
- Web 框架：NestJS
- API 风格：REST API + OpenAPI / Swagger
- 数据库：PostgreSQL
- ORM 与迁移：Prisma
- 缓存与限流：Redis
- 异步任务：BullMQ
- 文件存储：国内可部署的 S3 兼容对象存储
- 认证：手机号、短信验证码、密码、JWT Access Token、Refresh Token
- 部署：Docker；API 与 Worker 独立进程

### 3.2 架构形态

采用“模块化单体 + 独立 Worker”，不采用微服务。

```text
Expo / React Native App
          |
          | HTTPS + REST API
          v
NestJS API 进程
  |-- PostgreSQL：唯一业务数据源
  |-- Redis：缓存、验证码、限流和队列
  |-- S3 兼容对象存储：图片、漫画、影片和导出文件
  `-- BullMQ：提交异步任务
                |
                v
          NestJS Worker 进程
          |-- AI 生成
          |-- 图片/视频处理
          |-- PDF 与备份
          `-- 通知发送和延迟清理
```

API 与 Worker 位于同一个后端仓库，复用领域类型、数据库访问和基础设施适配器，但必须能够独立启动、扩容和部署。

### 3.3 后端职责

App 不得直接访问 PostgreSQL、Redis 或对象存储管理接口。所有认证、情侣归属、私密内容、额度和状态转换均由 NestJS Guard 与 Service 校验。

对象存储、短信、推送和 AI 供应商必须通过接口适配器隔离，业务模块不得直接依赖某一家云厂商的 SDK，以便在国内云服务之间替换。

## 五、认证设计

### 5.1 第一版范围

- 手机号 + 密码登录；
- 短信验证码注册；
- 短信验证码找回密码；
- Access Token + Refresh Token；
- 多设备会话查看；
- 退出当前设备或指定设备；
- 登录、验证码和密码重置限流；
- 多次失败后的临时账号锁定；
- 敏感操作重新验证密码或短信验证码。

微信、QQ、Apple 等第三方登录不在第一版实现范围。身份模型可以支持未来增加认证方式，但本期不建立对应业务接口或页面。

### 5.2 安全约束

- 密码使用 Argon2id 生成哈希；
- Refresh Token 和短信验证码只存摘要，不存明文；
- Access Token 使用短有效期；
- Refresh Token 使用轮换机制，发现重放时撤销令牌族；
- 日志不得记录密码、验证码、完整 Token 或完整手机号；
- 账号注销采用状态机和延迟清理，不直接级联删除共同内容。

## 六、API 全局契约

### 6.1 基础约定

- 基础路径：`/api/v1`
- 传输格式：UTF-8 JSON
- API JSON 字段：`camelCase`
- 数据库字段：`snake_case`
- Bearer Access Token 用于用户接口认证
- OpenAPI / Swagger 是开发期机器可读和交互式契约
- 公开项目页面只展示业务 API，不展示内部管理接口、密钥、供应商配置或风控阈值

### 6.2 成功响应

```json
{
  "data": {},
  "meta": null,
  "requestId": "req_..."
}
```

列表响应的 `meta` 至少可以包含 `nextCursor` 和 `hasMore`。

### 6.3 错误响应

```json
{
  "error": {
    "code": "STABLE_BUSINESS_CODE",
    "message": "可向用户展示的中文说明",
    "details": null
  },
  "requestId": "req_..."
}
```

错误码必须稳定并可由 App 映射为页面状态。内部异常、SQL、对象存储路径和第三方供应商原始响应不得直接返回给 App。

### 6.4 一致性规则

- 列表默认使用游标分页；
- 创建情侣邀请、AI 任务、回忆册、支付订单和导出任务等关键操作支持 `Idempotency-Key`；
- 可被双方编辑的重要资源包含 `version`，更新时使用乐观锁；
- 所有时间以 UTC 写入 PostgreSQL，API 使用 ISO 8601；
- 多表状态转换必须使用数据库事务；
- API 不信任客户端传入的 `userId` 或 `coupleId`，数据归属从认证上下文解析并再次校验。

## 七、数据库全局原则

- 核心主键统一使用 UUID；
- 核心表包含 `created_at`、`updated_at`；
- 可恢复或需要异步清理的业务内容使用 `deleted_at` 软删除；
- 用户私有数据以 `owner_id` 标识；
- 共同数据以 `couple_id` 标识；
- 枚举在数据库和 API 中使用稳定英文代码，中文只用于 UI；
- 核心用户、关系、额度和状态使用关系型字段；
- AI 参数快照、回忆册版面等结构化但可演进的数据可以使用 `jsonb`；
- 文件二进制不得进入 PostgreSQL，数据库只保存对象键、MIME、大小、哈希、状态和业务归属；
- 解除情侣关系不得直接级联删除共同日记、照片、时刻、作品或回忆册；
- 外键、唯一约束、检查约束和查询索引必须在表设计中明确，不只依赖应用层校验。

数据库不暴露公网访问。用户授权由 NestJS Guard 和 Service 执行；Repository 查询必须包含用户/情侣归属条件，避免只查询资源 ID 后再进行不完整判断。

## 八、文件和异步任务

### 8.1 文件流程

客户端先向 NestJS 请求受限上传凭证，再直接上传至对象存储，最后调用完成接口登记文件元数据。下载私密文件时由后端签发短期访问地址。

对象键由服务端生成，客户端不得自行指定完整存储路径。删除业务记录时先将文件标记为待清理，再由 Worker 执行幂等删除。

### 8.2 任务流程

AI、影片、PDF、备份和批量清理使用统一任务模式：

1. API 校验身份、情侣关系、额度和幂等键；
2. 在数据库事务中创建业务记录与任务记录；
3. 将任务提交到 BullMQ；
4. Worker 获取任务并更新进度；
5. 结果写入对象存储并登记文件；
6. 成功时结算权益并发送通知；
7. 技术失败时按规则重试、回滚预扣或进入人工可观察状态。

任务必须具有稳定状态机、最大重试次数、超时、幂等和失败补偿策略。

## 十、开发阶段路线

### 阶段 0：工程基础

建立 NestJS、Prisma、PostgreSQL、Redis、配置校验、结构化日志、统一异常、请求追踪、Swagger、Docker 和测试基础设施。

完成标准：健康检查、数据库迁移、Redis 连接、统一响应与错误、测试数据库和 CI 均可重复运行。

### 阶段 1：账号与用户

实现手机号认证、验证码、JWT、Refresh Token、用户资料、设备会话和密码重置。

完成标准：注册、登录、刷新、退出、找回密码和会话撤销均具备正常与反向安全测试。

### 阶段 2：情侣关系

实现邀请、确认、绑定、等待、失效、已有关系拦截、情侣资料和解除关联状态机。

完成标准：并发接受同一邀请码不会产生重复关系，非关系成员不能读取或修改关系数据。

### 阶段 3：文件与共同记录

实现受限上传、文件元数据、日记、照片、标签、私密/共同可见、伴侣回应和共同记录搜索。

完成标准：私密记录不会通过列表、详情、搜索、回应或文件地址泄露给伴侣。

### 阶段 4：重要时刻

实现重要章节、关联原始记录、纪念日、共同提醒、时光胶囊和悄悄留言索引。

完成标准：未到期胶囊正文和附件在所有接口中均不可读取；提醒与留言不会混为同一业务实体。

### 阶段 5：童话工坊与权益

实现创作草稿、素材选择、主角设定、会员权益、AI 积分、AI 任务、Worker、作品和通知。

完成标准：任务创建与额度预扣原子完成；重复请求不会重复扣费；技术失败按规则退款；结果文件保持私密。

### 阶段 6：共同回忆册

实现书架、建册、主题、素材引用、统一页面编排、章节页序、补页、阅读状态和删除管理。

完成标准：来源内容权限变化后不会通过回忆册泄露；双方并发调整页序可检测冲突；不依赖宠物数据。

### 阶段 7：我的、设置与系统能力

实现会员展示、通知偏好、隐私设置、存储统计、反馈、协议版本、版本检查、数据导出与账号注销。

完成标准：设置会实际影响通知和默认可见范围；注销和数据清理具有可追踪状态，不误删情侣共同内容。

### 阶段 8：上线加固

完成权限矩阵、并发、限流、备份恢复、对象存储生命周期、审计、告警、压测、灰度和灾难恢复验证。

完成标准：所有高风险接口包含越权、重放、重复提交、失败回滚和敏感信息泄露测试，并形成上线检查记录。

每个阶段的实施文档必须列出前置依赖、NestJS 模块、REST API、数据表、测试用例、完成标准和明确不做事项。未通过当前阶段验收，不进入依赖该阶段的后续业务实现。

## 十一、测试与安全验收

- Service 单元测试覆盖状态机与业务规则；
- Repository 集成测试使用真实 PostgreSQL 测试库；
- API 端到端测试覆盖认证、权限、幂等、分页和事务回滚；
- Worker 测试覆盖重试、进度、超时、幂等和失败补偿；
- 每个共同数据模块必须包含“非当前情侣成员不可访问”的反向测试；
- 每个可见性入口必须包含“`PRIVATE` 内容不可被伴侣读取”的反向测试；
- 文件访问测试必须验证过期地址、越权对象键和已删除资源；
- 公开资料测试必须验证页面入口、API 条目、表字段、公开清单、无本地绝对路径和无敏感配置。

## 十二、规格完成后的实施边界

本任务不创建 NestJS 后端工程，不执行 App 的 Supabase 迁移，不修改 App API 调用，也不删除现有分支。后端工程和 App 接入应在后续独立任务中依据这些资料实施。
