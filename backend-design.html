ARCHITECTURE

请求、事务与异步执行分层

NestJS API 负责认证、授权与同步事务；PostgreSQL 是业务事实源；Redis 与 BullMQ 承接可重试任务；对象存储仅经文件服务签发受限上传和下载。

  • 受保护请求先经会话、用户和情侣关系 Guard，再到所属领域 Service。
  • 同步写入与可靠待投递记录同一事务提交，Worker 以稳定任务 ID 补投和执行。
  • 读取始终复核内容来源与当前权限，关系状态变化不会绕过既有可见性规则。

RELATIONSHIPS

关键关系与一致性

  • records 是日记与照片集合的统一根，扩展表以 record_id 一对一关联。
  • 情侣关系通过 members 槽位约束有效成员数量；解除操作冻结共同历史而不是级联删除。
  • 积分余额只能由不可变账本流水变动；文件删除与导出由异步任务执行并在执行时复核引用。
  • 回忆册的来源、章节和页面排序在 PostgreSQL 事务内检查，读取时继续复核来源授权。

DELIVERY ROADMAP

开发路线

  1. 阶段 0 建立基础设施、观测、可靠任务投递与恢复策略。
  2. 阶段 1–2 交付身份、账户与情侣关系的认证、并发和生命周期边界。
  3. 阶段 3–4 交付文件、共同记录、重要时刻、提醒与胶囊。
  4. 阶段 5–7 交付工坊、权益、回忆册、设置、导出和系统能力。
  5. 阶段 8 完成安全、压测、迁移、灰度和客户端替换验收。
